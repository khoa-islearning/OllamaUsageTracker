What it does

A macOS utility whose product is a Notification-Center widget: it always shows your remaining Ollama Cloud credit, how much of the prepaid allowance you've burned, purchased top-up credit, and the renewal date. The companion host app exists purely to walk you through setup and let you verify the connection.

Outcome: glanceable balance + early depletion warning · zero server · zero data collection.

Business requirement (why it exists)

  • Ollama Cloud grants a prepaid USD allowance per period — heavy API use depletes it silently.
  • The balance must be glanceable at all times (the website isn't), with a warning before it runs out.
  • Trust constraint: the API key never leaves the machine (Keychain, not the app, not a server); only ollama.com is contacted.
  • Adoption constraint: installable by a non-developer from a DMG, with a one-command setup.

Product features

  • Widget (Small + Medium): remaining USD, allowance progress, purchased-credit chip, renewal date.
  • Auto-refresh every 15 min; turns orange above 80% spent.
  • Setup panel: key-status detection (✅/⚠️/🔒), copy-paste Terminal commands, troubleshooting.
  • "Test connection" (on click): one-line balance summary + 401 guidance.
  • One-command release: make release VERSION=x.y → verified DMG.

Technical features

  • Targets (2): OllamaUsageTracker.app — SwiftUI host · OllamaUsageRemainingBalanceWidget.appex — WidgetKit extension (kind "OllamaBalanceWidget", Small/Medium), embedded in Contents/PlugIns/.
  • Bundle-ID nesting: com.khoanguyenpersonalteam.OllamaUsageTracker ← child …Tracker.OllamaUsageBalanceExtension (OS-validated rule).
  • Widget runtime: TimelineProvider + reload policy .after(15 min); the OS archives the SwiftUI view into a static snapshot — no code runs between refreshes (≈0.05% duty cycle).
  • Keychain (Security.framework): attributes-only existence probe (no launch prompts) · secret read gated behind a click or the scheduled refresh · "Always Allow" ACL per code-signing identity.
  • Networking: URLSession over HTTP/3 (QUIC) → ollama.com/api/balance, Bearer auth, ≈401 ms cycle; HTTP 401 modeled as data ("rotate your key"); sandbox egress via the network-client entitlement on both targets.
  • Robustness: errors are timeline entries (widget never blank); presence states found/missing/locked/error.
  • No third-party Swift dependencies; pure SwiftUI + WidgetKit + Security + URLSession.

Data plane vs view plane — the layering that makes this debuggable

DATA (provider + models)

  • Keychain → URLSession → JSONDecoder → BalanceEntry (value struct)
  • math lives once: remaining = included + purchased
  • errors are entries, not throws — timeline never empty

VIEW (entry → pixels)

  • pure function of entry; no fetch, no Date.now() in body
  • .containerBackground(…, for: .widget) — mandatory, else OS refuses render
  • OS archives the view to a snapshot; nothing runs until next policy

Why you should care

  • UI bug? ask "what did the entry contain?" — chip the entry, not breakpoints
  • host app re-decodes its own copy so the widget file could ship frozen
  • two processes share nothing (no App Groups) — hence the Keychain setup step

The four real failures — know these, you can explain the app

Build fatal

Log: Build input file cannot be found: …/OllamaUsageBalance/Info.plist — target pointed at a nonexistent path.

Fix: OllamaUsageRemainingBalanceWidget/Info.plist (carries NSExtensionPointIdentifier = com.apple.widgetkit-extension).

Embedding fatal

Log: Embedded binary's bundle identifier is not prefixed with the parent app's — npm-scope rule, enforced by validation.

Fix: child id …OllamaUsageTracker.OllamaUsageBalanceExtension.

Runtime card

Symptom: warning card persisted after adding containerBackground — a stale DerivedData extension was still the registered one.

Fix: rebuild real DerivedData, pluginkit -a the fresh .appex, re-add widget. macOS renders the registered build, not your latest.

Sandbox egress

Symptom: the widget fetches fine, but the app's Test connection fails with “A server with the specified hostname could not be found” — a fake DNS error. App Sandbox had no com.apple.security.network.client entitlement on the host target, so egress (and even DNS) is silently denied.

Fix: ENABLE_OUTGOING_NETWORK_CONNECTIONS = YES on the app target; the widget already had it. Lesson: in a sandboxed app, “hostname not found” can mean “sandbox said no”, not “no DNS”.

Script bug

Symptom: ARCHIVE_SIGNING_ARGS[@]: unbound variable — macOS bash 3.2 errors expanding empty arrays under set -u.

Fix: explicit signed/unsigned branches instead of splicing arrays.
